# 日常使用

> 只想快速把系统跑起来用，看这一页就够了。
> 完整部署、备份、故障排查见 [部署运维手册](部署运维手册.md)。

---

## 启动

```powershell
cd D:\Docment\supervision-qc
docker compose up -d
```

**就这一条，不需要第二步。** 数据初始化已内置在 api 容器入口，且是幂等的
（已有数据会跳过），所以「首次」和「平时」命令完全一样。

等约 30–60 秒，然后打开浏览器。

| 地址 | 说明 |
| --- | --- |
| <http://localhost:8080> | 管理后台 |
| <http://localhost:8080/api/v1/docs> | 接口文档 |

管理员登录后，左侧「**用户与授权**」可为用户分配项目与角色 ——非管理员必须至少授权一个项目，否则该用户登录后看不到任何项目数据。

登录：`admin` / `Admin@12345`

> 另有示例角色账号 `engineer`（监理工程师）、`expert`（审核）、`viewer`（只读），
> 密码相同，均已绑定示例项目。用它们可以直观看到「不同角色可见的数据范围不同」——
> 例如 `viewer` 只能查看，不能上传规范或发起评估。

## 确认是否就绪

```powershell
docker compose ps
```

`api` 与 `web` 都显示 `healthy` 即可。想看启动过程：

```powershell
docker compose logs -f api
```

看到 `[entrypoint] 初始化完成` 就说明数据也准备好了。

也可以直接问接口：

```powershell
curl.exe -s http://localhost:8080/api/v1/health
```

关注 `"status": "ok"`、`embedding.degraded: false`、`vector_index_default.size` 大于 0。

---

## 停止

```powershell
docker compose down
```

数据**不会丢**：`down` 只删容器，命名卷保留，下次 `up -d` 接着用。

> 只有 `docker compose down -v` 才连数据卷一起删（彻底重置，会清空所有文档与任务）。

---

## 不想敲命令

双击项目根目录的 **`start.bat`**：效果与 `docker compose up -d` 相同，另外会做环境自检、
检查 API Key 是否为空、主动等接口健康、打印访问地址，出错时停住窗口方便看报错。

停止则双击前先在终端执行 `docker compose down`，或运行 `.\start.ps1 -Down`。

## 改了东西之后怎么重启

| 改了什么 | 重启命令 |
| --- | --- |
| 后端代码（`backend/app/`） | `docker compose up -d --build api` |
| 前端代码（`frontend/src/`） | `docker compose up -d --build web` |
| `deploy/.env` 配置 | `docker compose up -d` |
| 什么都没改，只是关机重开 | `docker compose up -d` |

## 另一种模式：本机开发（改代码有热更新）

适合调前后端代码，Vite 热更新、改完即生效，不用重建镜像：

```powershell
cd D:\Docment\supervision-qc
.\start-local.ps1
```

- 数据层仍用 Docker，前后端跑本机进程
- 访问 <http://127.0.0.1:5173>
- **Ctrl+C 一次全停**（数据层容器保留）

两种模式的数据卷相互独立，所以本机模式首次启动要带 `-Seed` 初始化数据：

```powershell
.\start-local.ps1 -Seed
```

> 双击 `start-local.bat` 也可以。

## 常见情况

**页面打不开？**
先 `docker compose ps` 看 `web` 是否 healthy。若刚启动，再等 30 秒。
仍不行看日志：`docker compose logs --tail 50 api`。

**检索返回空 / 找不到条款？**
```powershell
curl.exe -s http://localhost:8080/api/v1/health
```
看 `vector_index_default.size` 是否为 0。为 0 说明索引没建好，执行：

```powershell
docker compose exec api python scripts/seed_data.py
```

**回答很慢或报错？**
多为大模型侧问题。确认 `deploy/.env` 里 `DEEPSEEK_API_KEY`、`SILICONFLOW_API_KEY` 已填写且有效：

```powershell
docker compose exec api env | findstr /I "API_KEY"
```

没有 Key 也能跑通全链路（走确定性假模型，用于验证功能而非真实推理）：

```powershell
.\start.ps1 -Offline
```

**端口 8080 被占用？**
在 `deploy/.env` 里加一行 `WEB_PORT=8090`，然后 `docker compose up -d`。

**想知道图谱/知识库里的数据状况？**
后台「知识图谱」页看节点统计；「系统与审计」页看指标与操作日志。
新增规范后如需抽取图谱：

```powershell
docker compose exec api python scripts/extract_kg_all.py
```

## 命令速查

```powershell
docker compose up -d                    # 启动（含自动初始化数据）
docker compose ps                       # 查看状态
docker compose logs -f api              # 跟踪后端日志
docker compose down                     # 停止（数据保留）
docker compose up -d --build api        # 改后端后重建
docker compose down -v                  # 彻底重置（删数据，慎用）
```
